题目要求重述：
> 系统主要实现家庭日常财务账目的管理，包括收支分类的管理、收支的管理、收支查询、汇总统计；对于汇总统计要求能按家庭成员、时间（年、月、周、日）来查询汇总，能对各种类别的收支进行统计分析，统计分析的结果能以文字、表格、图形等多种方式进行查询。

# 一、项目背景与目标
开发背景
随着现代家庭经济活动日益复杂，家庭收入与支出呈现出碎片化、多渠道的特征（如不同 APP、不同平台 IOS & Android），不同成员、不同来源的记账数据天然存在生态隔离和权限封锁；此外，虽然目前已经出现了众多运行在移动端的记账程序，但是受限于手机屏幕尺寸和App的封闭沙盒，当面对长篇大论的账单（比如年底复盘、或者清理几个月前的旧账）时，在小屏幕上一点点敲字、选分类是非常让人崩溃的；不仅如此，普通的记账产品只是一个“数据存储产品”，缺乏==算力支持的复杂深入数据分析==和清晰、高效且美观的数据呈现。


开发目标
基于以上提到的现有记账产品存在的痛点，我们充分发挥 Web 端跨平台、免安装的优势，打破生态隔离与单机模式；同时，我们通过极致易用的操作界面，极大地降低了数据录入的难度，同时支持数据批量导入（和自动识别功能），降低了用户的使用门槛；此外，我们实现了==家庭组功能==，能够通过添加家庭成员，实现家庭成员之间记账数据的共享和联合统计分析；不仅如此，我们依托后端的计算能力与前端丰富的数据呈现，对记账数据进行自动数据清洗与分类统计，（并支持==自动生成专业的数据分析报告==），极大地便利了用户充分了解和掌握个人及家庭的收支情况。


# 二、用户画像与角色分析

1. 普通独立记账用户
特征：是具有个人财务管理需求的独立个体（如单身职场人士、学生等），独立使用系统，不归属于任何家庭组
目标：追求高效的记账体验，反感繁琐的手动录入；需要清晰掌握个人资产流向，期望系统能提供深度的数据分析以辅助个人消费决策。

痛点：
+ 现有移动端记账产品操作繁琐，小屏幕录入效率低，处理大量历史账单时体验极差
+ 现有产品数据分析能力弱，只能看到数字，无法发现消费规律
+ 不同平台的收支数据相互隔离，难以统一管理

2. 家庭用户
（1）家庭组管理员
特征：负责管理家庭财务的成员，通常是家庭中主导财务决策的人，对家庭整体收支情况有掌控需求。
目标：在普通用户目标的基础上，还希望能够管理家庭成员、维护收支分类、掌握家庭整体财务状况。

痛点：
+ 各成员记账分类标准不统一，汇总后数据混乱
+ 缺乏跨成员的联合统计分析能力，无法直观了解家庭整体财务健康状况
+ 无法对家庭成员的记账行为进行统一管理

（2）家庭组受邀成员
特征：属于普通用户，但是归属于家庭组，由家庭管理员统一管理。通常是家庭中的普通成员，如配偶、子女等，对财务管理的主动性相对较低，更注重记账操作的简便性。
目标：以最低的操作成本完成日常收支记录，无需关心系统配置和分类管理等事务，同时能够查看家庭整体的财务状况，了解家庭收支概况。

痛点：
+ 不愿花大量时间学习和配置记账系统
+ 希望记账操作尽可能简单，最好一步完成
+ 在各支付平台账单格式各异，难以统一到一处进行管理和分析

# 三、功能性分析
## 3.1 用户管理
**作为一个新用户，我希望能够注册账号，以使用系统的各项功能。**
+ 用户需要提供手机号或邮箱（作为登录账号）、密码、昵称才能完成注册
+ 手机号或邮箱不能与已注册账号重复，重复时给出明确提示
+ 昵称仅用于显示，允许重复
+ 注册成功后可直接登录

**作为一个已注册用户，我希望能够登录系统，以便访问我的账目数据。**
+ 使用手机号或邮箱配合密码登录
+ 登录失败时统一提示"账号或密码错误"，不透露具体失败原因-- 安全性考虑
+ 登录成功后进入系统首页

**作为一个已登录用户，我希望能够管理个人信息，以便保持资料的准确性。**
+ 可以修改昵称
+ 可以修改密码，修改密码需要验证旧密码

## 3.2 收支分类管理
**作为一个用户，我希望系统提供默认的收支分类，以便开始记账时不需要从零配置。**
+ 系统内置一套覆盖日常消费场景的分类，包含餐饮、交通、购物、住房、医疗、教育、娱乐、工资、奖金等常用类别，并提供”其他“类别覆盖特殊情况
+ 系统内置分类不可删除

**作为一个独立用户，我希望能够自定义收支分类，以便记录符合个人实际情况的账目。**
+ 可以新增自定义分类，并指定该分类属于收入还是支出
+ 可以自定义分类的名称
+ 可以删除自定义分类，但已被使用的分类不能删除，需先将关联记录迁移到其他分类
+ 独立用户加入家庭组后，个人分类自动提交至家庭管理员审核，审核通过后并入家庭分类

**作为一个家庭成员，我希望能够提议新增家庭分类，以便满足个人特殊的记账需求。**
+ 可以提交新增分类申请，填写分类名称和收支类型
+ 申请提交后等待家庭管理员审核
+ 审核通过后新分类对全体家庭成员生效
+ 审核不通过时收到拒绝通知

**作为一个家庭管理员，我希望能够统一管理家庭分类，以便保证家庭成员记账标准的一致性。**
+ 可以直接新增、修改家庭分类，无需审核，立即对全体成员生效
+ 可以审核家庭成员提交的分类申请，选择通过或拒绝
+ 审核通过时可以选择将新分类作为独立类别新增，或与某个已有分类合并
+ 可以删除家庭分类，删除前需将关联记录迁移到其他分类

## 3.3 收支记录管理
**作为一个用户，我希望能够快速记录一笔收支，以便及时记录每一笔财务往来。**
+ 记录一笔收支需要填写：收支类型（收入/支出）、分类、金额、日期、备注（可选）
+ 金额必须为正数
+ 日期默认为今天，可以手动修改为任意日期

**作为一个用户，我希望能够修改已记录的收支，以便纠正录入错误。**
+ 可以修改自己记录的任意一笔收支的所有字段
+ 修改后数据实时更新

**作为一个用户，我希望能够删除错误的收支记录，以便保持账目的准确性。**
+ 可以删除自己记录的任意一笔收支，无需审核
+ 删除前需要二次确认，防止误删

**作为一个用户，我希望能够查询历史收支记录，以便回顾某段时间内的账目。**
+ 可以按时间范围筛选记录
+ 可以按收支类型筛选记录
+ 可以按分类筛选记录
+ 可以按金额范围筛选记录
+ 多个筛选条件可以组合使用
+ 查询结果按日期倒序排列

**作为一个用户，我希望能够批量导入历史账单数据，以便将过去的收支记录迁移到系统中。**
+ 支持导入系统标准模板Excel文件
+ 支持导入微信账单原始CSV文件，系统内置默认字段映射规则，将"交易时间"映射为日期、"交易类型"映射为收支类型、"商品"映射为备注，未能映射的字段置空
+ 支持导入支付宝账单原始CSV文件，系统内置默认字段映射规则，将"记录时间"映射为日期、"收支类型"映射为收支类型、"分类"映射为分类、"备注"映射为备注，未能映射的字段置空
+ 用户可以在导入前预览映射结果，并手动调整字段映射关系
+ 导入完成后显示成功条数和失败条数，失败记录给出原因

**作为一个家庭成员，我希望能够控制自己记账数据的可见范围，以便在隐私与家庭共享之间自主选择。**

- 每条收支记录在创建时可以设置可见范围：仅自己可见、家庭成员可见
- 可以在个人设置中配置默认可见范围，新建记录时自动沿用默认设置
- 可以随时修改已有记录的可见范围设置
- 家庭管理员可以查看所有成员的所有记录，不受可见范围限制


## 3.4 汇总统计
**作为一个用户，我希望能够按时间维度查看收支汇总，以便了解不同时间段内的财务状况。**
+ 可以查看某一天的收支汇总
+ 可以查看某一周的收支汇总
+ 可以查看某一月的收支汇总
+ 可以查看某一年的收支汇总
+ 汇总结果包含总收入、总支出、结余三项数据

**作为一个用户，我希望能够按分类查看收支统计，以便了解各类消费的占比情况。**
- 可以查看各分类的收支金额及其占总额的百分比
- 统计结果按金额从高到低排列

**作为一个用户，我希望统计结果能以多种形式展示，以便直观地理解财务数据。**
- 支持以文字形式展示汇总数字
- 支持以表格形式展示各分类明细
- 支持以图形形式展示统计结果，包括分类占比饼图、收支对比柱状图、收支趋势折线图

**作为一个家庭成员，我希望能够查看家庭整体的收支统计，以便了解家庭整体财务状况。**
- 可以查看家庭所有成员的收支汇总
- 可以按家庭成员维度进行统计分析，了解各成员的收支占比
- 查看其他成员的记录明细时，只能看到对方设置为"家庭成员可见"的记录

**作为一个家庭管理员，我希望能够查看所有成员的记录明细，以便全面掌握家庭财务状况。**
- 可以查看所有家庭成员的收支记录明细
- 查询条件与个人记录查询一致，额外支持按成员筛选

## 3.5 首页仪表盘
**作为一个用户，我希望登录后能立即看到关键的财务信息，以便快速掌握当前财务状况。**
- 首页展示本月总收入、总支出、结余三个数字卡片
- 首页展示本月各分类支出占比饼图
- 首页展示最近一周收支趋势折线图
- 首页展示最近10条收支记录列表
- 家庭成员登录后额外展示家庭本月整体收支概况


## 3.6 家庭组管理（拓展）
**作为一个用户，我希望能够创建家庭组，以便与家庭成员共享账目数据。**
- 填写家庭名称即可创建家庭组，创建者自动成为家庭管理员
- 创建后系统自动生成邀请码，管理员可以将邀请码分享给家庭成员
- 一个用户只能归属于一个家庭组

**作为一个用户，我希望能够通过邀请码加入家庭组，以便参与家庭共同记账。**
- 输入有效的邀请码提交加入申请
- 申请提交后等待家庭管理员审核
- 审核通过后正式成为家庭成员，个人分类自动提交家庭管理员审核

**作为一个家庭管理员，我希望能够管理家庭成员，以便维护家庭组的正常运转。**
- 可以查看所有家庭成员列表
- 可以审核成员的加入申请，选择通过或拒绝
- 可以移除家庭成员，被移除成员的历史记录保留但不再参与家庭统计
- 可以重新生成邀请码，旧邀请码立即失效
- 可以将管理员身份转让给其他成员

## 3.7 扩展功能
- 微信/支付宝账单字段映射规则支持用户自定义保存，下次导入时直接复用
- 账单自动识别：支持上传账单截图，OCR识别后自动填充记账表单
- 数据分析报告：支持将统计结果导出为PDF报告

# 四、非功能性需求
## 4.1 安全性
+ 所有接口必须在登录后才能访问，未登录用户的请求一律拒绝
+ 用户只能访问和操作自己的数据，不能越权访问其他用户的记录
+ 密码不能以明文形式存储，需经过加密处理后保存
+ 家庭成员查看其他成员的记录明细时，只能看到对方设置为"家庭成员可见"的记录；家庭管理员可查看所有成员的全部记录，不受可见范围限制

## 4.2 易用性
+ 完成一次记账操作的交互步骤应尽可能少
+ 所有错误提示信息应清晰易懂，帮助用户理解出错原因并知道如何修正
+ 批量导入功能应提供预览步骤，让用户在正式导入前确认数据映射结果，避免导入错误数据

## 4.3 数据准确性
+ 金额字段保留两位小数，计算结果不得出现精度丢失
+ 统计数据与记录明细数据必须保持一致，不能出现汇总数字与明细对不上的情况
+ 批量导入完成后需告知用户成功条数与失败条数，失败记录需给出明确原因

## 4.4 可靠性
+ 删除操作需二次确认，防止用户误操作导致数据丢失
+ 系统应对用户的非法输入进行校验，拒绝不合法的数据写入

## 4.5 兼容性
+ 系统基于 Web 端开发，需兼容主流浏览器（Chrome、Edge、Firefox）
+ 页面布局需适配常见的PC屏幕分辨率，充分利用大屏幕优势提升操作效率


# 五、约束条件
## 5.1 时间约束
+ 项目需在第15周（6.9日）前完成开发并部署上限，供老师验收
+ 需合理规划各模块的开发优先级，==确保基础功能优先完成==

## 5.2 团队约束
+ 开发团队为在校学生，人数优先，技术选型需在团队能力范围内
+ 每位成员需承担实质性的后端开发工作，不能仅负责文档或前端页面

## 5.3 技术约束
+ 系统需部署在云服务器上，通过浏览器访问，无需安装客户端
+ 前端基于 Vue3 开发，后端基于 Spring Boot开发，数据库使用 MySQL
+ 系统需兼容主流浏览器，无需适配移动端

## 5.4 数据约束
+ 系统为课程大作业，不作为商业产品运营，并发访问量和数据规模较小，性能不作为主要考量指标
